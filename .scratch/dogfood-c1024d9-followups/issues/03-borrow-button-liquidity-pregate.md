# 03 — Pre-gate the market-row BORROW button when no liquidity is postable

> *This was generated by AI during triage.*

**Category:** bug

**Decision (maintainer, 2026-07-28):** Fix it — pre-gate the market-row `BORROW` button itself so a borrower can't even open the borrow flow when no liquidity exists for the market, rather than relying on the modal to catch it after the fact.

**Current behavior:** `MarketRowDetail.tsx`'s market-row `BORROW` button is enabled whenever the wallet holds an eligible stream, the market hasn't matured, and the wallet is connected — it does not check whether any lender liquidity has actually been posted for the market. `web/tests/e2e/borrow.feature`'s "Error state — no liquidity posted for this market" scenario documents this: the enabled market-row button opens the "BORROW AGAINST STREAM" modal, and only *inside* the modal (after selecting a stream and clicking "APPROVE STREAM" — an on-chain approval transaction) does the UI surface `NO LIQUIDITY POSTED AT ANY RATE` and disable the modal's own submit button.

Note for context: the modal's own submit button is already disabled at that point, so an actual `createBorrowerLoanPool` (or equivalent borrow) submission was never reachable with zero liquidity — but the current flow still lets the user get as far as signing a real on-chain `APPROVE STREAM` transaction for a borrow that was always going to be rejected, which is the concrete harm worth closing off, not just UX friction.

Separately and correctly, `c1024d9` fixed an accessible-name collision so the per-stream disabled placeholder in `PositionList.tsx`'s `StreamCard` (rendered whenever a stream has no postable liquidity) now reads `BORROW STREAM {id}` instead of bare `BORROW` — see `docs/solutions/ui-bugs/stream-card-borrow-button-accessible-name-collides-with-market-row-borrow.md`. That fix did not touch the market-row button's own enablement condition, which is what this ticket closes.

**Desired behavior:** The market-row `BORROW` button should be disabled, with a caption, when the market currently has zero postable liquidity at any rate — using the same liquidity signal already computed for the per-stream placeholder (`PositionList.tsx`'s `teaserBps` derived from `useLendingLiquidity` + `borrowTeaserBps`; `teaserBps === null` means no liquidity at any rate for that market). Reuse the existing `NO LIQUIDITY POSTED AT ANY RATE` caption text for consistency with what the modal already shows in this case, joining the existing `borrowCaption` fallback chain (disconnected → market not lending-enabled/matured → no eligible streams → **no liquidity for this market** → enabled).

Once a market has any liquidity posted at any rate, the button re-enables immediately (this is a live gate, not a one-time check) — a lender posting liquidity should unblock borrowers without a page reload.

**Key interfaces:**
- `MarketRowDetail`'s `borrowCaption` computation — needs a new liquidity-derived branch, sourced from the same market-level liquidity read already used elsewhere (`useLendingLiquidity`/`teaserBps`), not a new independent liquidity fetch
- The modal's own no-liquidity handling (`NO LIQUIDITY POSTED AT ANY RATE` caption + disabled submit) stays as-is — this is defense in depth, not replaced by the pre-gate

**Acceptance criteria:**
- [x] Market-row `BORROW` button is disabled with a `NO LIQUIDITY POSTED AT ANY RATE`-style caption when the market has zero postable liquidity at any rate, for a wallet that otherwise has an eligible stream
- [x] The button re-enables (without a page reload) once liquidity is posted for the market
- [x] `web/tests/e2e/borrow.feature`'s "Error state — no liquidity posted for this market" scenario updated: the market-row `BORROW` button itself is now the thing asserted disabled-with-caption, rather than opening the modal to discover it — the in-modal assertions can be dropped or kept as a secondary defense-in-depth check per whoever implements this
- [x] A component-level test (alongside `web/tests/components/position-cards.test.tsx`'s existing "no real liquidity" coverage) asserts the market-row button's disabled state directly, not just the per-stream placeholder
- [x] No user path reaches `APPROVE STREAM` or any on-chain borrow-adjacent transaction when zero liquidity is posted for the market

**Out of scope:**
- The per-stream `StreamCard` placeholder rename (`BORROW STREAM {id}`) — already fixed in `c1024d9`, not touched here
- Removing the modal's own no-liquidity handling — keep it as a second line of defense in case liquidity is withdrawn between the market-row check and modal submission

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

**Plan:** `docs/plans/2026-07-28-001-fix-dogfood-c1024d9-borrow-gate-and-fee-approve-plan.md` (U1). Implementation-ready via `/ce-plan` on 2026-07-28. Do not re-litigate product decisions — execute U1 from that plan.

## Comments

**2026-07-28 (triage):** Re-triaged from the dogfood report's "Paper Cuts" section (stream-borrower persona, severity: low). Initially recommended `needs-triage` since the modal already blocks actual borrow submission with zero liquidity. Maintainer decided to fix it anyway — the concrete harm is that a user can still be walked into signing a real on-chain `APPROVE STREAM` transaction before discovering there's no liquidity, not just an extra click. Re-scoped to pre-gate at the market-row level using the same liquidity signal already computed for the per-stream card, and moved to `ready-for-agent`.

**2026-07-28 (ce-plan):** Linked to combined implementation-ready plan with ticket 04. This ticket maps to **U1** (market-row BORROW liquidity pre-gate + `borrow.feature` rewrite). Ticket remains `ready-for-agent` pending `/ce-work` (or equivalent) — plan only, no implementation in that session.

**2026-07-29 (implemented):** U1 landed on branch `fix/dogfood-borrow-gate-fee-buffer`. Rather than duplicating the ladder→teaser derivation, the shared definition of "empty" was extracted as `marketBorrowTeaserBps` in `web/lib/positions.ts`; `PositionList` and `MarketRowDetail` now both call it, so the market-row gate and the per-stream `NO LIQUIDITY` placeholder cannot drift apart (plan KTD1, and the divergence risk in the plan's risk table).

`MarketRowDetail`'s `borrowCaption` chain is now: `baseActionCaption` → `NO STREAMS AVAILABLE` → `NO LIQUIDITY POSTED AT ANY RATE`. The last branch fires only once `useLending` and `useLendingLiquidity` have settled; while either read is in flight the button stays disabled *without* the caption, so an unresolved read never renders as "empty" (plan KTD2).

Coverage: 6 new cases in `web/tests/components/markets-table.test.tsx` (empty ladder, live re-enable on posted liquidity, self-owned-liquidity-only still empty, both loading states, and caption priority vs `NO STREAMS AVAILABLE`). `borrow.feature`'s no-liquidity scenario now asserts the disabled market-row control and `no modal is open` — it never clicks through to `APPROVE STREAM`. Full unit suite 332 passed; full E2E suite run against a freshly bootstrapped local fork.
